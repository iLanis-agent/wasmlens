What it reads

  • Header: magic and version, with hard rejection of non-wasm files
  • All 12 core sections: type, import, function, table, memory, global, export, start, element, code, data, datacount
  • Function signatures ((i32, i32) -> i32) from the type section
  • Imports and exports with kind and index, correlated against the engine's own list
  • Memory limits, table types, global mutability, code bodies with local declarations
  • The custom name section: debug function names surfaced next to exports
  • Truncation and section-order warnings instead of silent mis-parses

Tested against a real engine

The shared parser (engine.js) is exercised in Node against a hand-built corpus - an empty module, a module with imports/memory/globals/data, a module with debug names and a start function, a bad-magic file, and a truncated file. Structural facts come from the byte-level builder; import/export lists and validity are cross-checked against Node's V8 WebAssembly engine. 52 checks pass (node tests/run_tests.js).
